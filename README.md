# Personal Nix System Configuration (nix-darwin + NixOS)

This repository contains a personal multi-host Nix setup: a MacBook Air managed with nix-darwin (`m5air`, `aarch64-darwin`) and a desktop PC managed with NixOS (`nixos`, `x86_64-linux`). It serves as an example of keeping system settings, packages, and user configuration in one place.

## How It Works

The configuration is split into modules by concern, so each machine can share the portable parts and add its platform-specific ones.

- `flake.nix` defines the flake inputs and wires both systems together. It outputs `darwinConfigurations."m5air"` (pinning the Homebrew taps and passing them to the darwin module via `specialArgs`) and `nixosConfigurations."nixos"`.
- `hosts/m5air.nix` is the macOS per-machine entry point: platform, hostname, and the Home Manager wiring (`home-manager.users.metru = import ../modules/common/home.nix`).
- `hosts/nixos.nix` is the NixOS per-machine entry point (same wiring, plus `hosts/nixos-hardware.nix`, generated by `nixos-generate-config`).
- `modules/common/` holds portable settings: system packages (cross-platform only), nix settings, and the Home Manager user config.
- `modules/darwin/` holds macOS-only settings: preferences, login items, activation scripts, Homebrew, and macOS-only desktop apps.
- `modules/linux/` holds NixOS-only settings: the primary user, the GNOME/NVIDIA desktop, sound, gaming, and networking.

The `home/` directory contains user configuration. Home Manager links these files into the home directory during a system switch.

The `Makefile` provides short commands for building and applying the configuration. It auto-detects the platform (`darwin-rebuild` on macOS, `nixos-rebuild` on Linux) and hostname.

## Third-party opencode skills

Some opencode skills live in upstream repos (e.g. `use-railway`). These are not committed to this repo — instead the source is declared as a GitHub tree URL, fetched at build time (via `fetchFromGitHub`), and overlaid into the opencode config.

To add a new third-party skill, add its GitHub tree URL to the `thirdPartyUrls` list in `modules/common/home.nix`:
```
https://github.com/<owner>/<repo>/tree/<rev>/<path-to-skill>
```
The last path segment becomes the skill name. Nothing else to touch.

To update an existing skill, bump the commit hash (`rev`) in its URL and rebuild:
```sh
git ls-remote https://github.com/railwayapp/railway-skills main | cut -f1
# paste the SHA into the URL in modules/common/home.nix
make switch
```

## Package placement

Keep `modules/common/` portable: packages that only exist on macOS (e.g. `raycast`, `rectangle`, `caffeine`, `shottr`, `tailscale-gui`) belong in `modules/darwin/packages.nix`, not `modules/common/packages.nix`. Check a package's platforms with `nix eval nixpkgs#<pkg>.meta.platforms`; if only darwin systems are listed, it goes in the darwin module.

## Tool sources

Three levels, from most to least preferred:

1. **Nix** — the default. System packages, CLIs, fonts, and macOS preferences live here.
2. **Homebrew** — fallback for macOS GUI apps that are impractical to package in nix (currently: Discord, WhatsApp, Parsec).
3. **mise** — per-project dev tooling (languages, compilers, interpreters). Mise itself is installed via nix; the tool versions it manages live in each project's `.mise.toml`.

## Use It As Inspiration

This setup is personal. Do not apply it unchanged to another machine.

To adapt it:

1. Add a new `hosts/<name>.nix` (or edit an existing host) with your username, home directory, user ID, hostname, and platform. macOS hosts import `modules/darwin/`; Linux hosts import `modules/linux/` and a generated `hosts/<name>-hardware.nix`.
2. Remove or replace settings that match the source machine (e.g. `modules/darwin/` preferences, the GPU setup in `modules/linux/desktop.nix`, gaming in `modules/linux/gaming.nix`).
3. Keep the packages and user configuration that fit your own workflow.
4. Update the flake inputs and system versions when needed.

The `home/` directory mirrors files in the home directory. Add user configuration there when you want Home Manager to manage it.

## Commands

Run these commands from the repository directory:

```sh
make build
```

Build the current machine's configuration without applying it.

```sh
make switch
```

Build and apply the configuration. This command requires `sudo`.

```sh
make help
```

Show the available Make targets.

To target a specific host: `make switch HOST=m5air` (or `HOST=nixos`).

On macOS, install Nix with flakes enabled and make sure the required macOS command line tools are available before you build the configuration. On NixOS, run `nixos-rebuild switch --flake .#nixos` (or `make switch`).
